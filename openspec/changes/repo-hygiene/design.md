# Design

## Context

See proposal.md (Why) for motivation and `specs/dev-quality/spec.md` for the requirements.
Current state that shapes the approach:

- **Tests.** `pytest.ini` sets `testpaths = tests` and defines the `live` marker.
  `pytest -m "not live"` selects 23 tests (29 deselected) and passes in about 0.1 s.
  `tests/conftest.py` puts `tests/` and the repo root on `sys.path` so the test modules can
  `import golden` and `importlib.import_module("evs_rebuild")`. `test_builders_golden.py`,
  `test_template_render.py` and `template_audit.py` load rebuilders by bare module name. The
  rebuild helpers are not collected (no `test_` prefix), but they are top-level modules.
- **Lint.** No `[tool.ruff]` exists. A contributor's user-level ruff config currently decides
  the result: 84 findings under one contributor's personal rules. With the rule set chosen
  below (`--isolated`, E/F/W/I/B/UP, line length 120) there are 129 findings: 54 E501, 24
  UP037, 16 E702, 11 I001, 11 F401, plus a few B904/B007/B905/F841/B017 and UP035. 48 are
  auto-fixable.
- **Bundle.** `docs/evidence/bundle/framework.js` (2.8 MB) has been tracked since the initial
  commit. It is cited in `docs/CAVEATS.md` (lines ~50 and ~175), `README.md` (URIMAP note and
  the "still to build" paragraph) and `docs/BACKLOG.md` D1. `autocalc doctor`
  (`src/autocalc/cli.py`) already scrapes the frontend version from `calculator.html` with
  `CBC-PortalCalculator/([0-9.]+)`.
- **CI.** Only `.github/workflows/copilot-setup-steps.yml` exists, and it is OpenSpec-generated.
  `uv.lock` is tracked and Python requires 3.11 or later.

## Goals / Non-Goals

**Goals:**
- A green CI gate on the first merge, with no allow-listed failures.
- A mechanical lint cleanup that leaves runtime behavior unchanged.
- One documented, reproducible way to get the current bundle locally.

**Non-Goals:**
- Raising test coverage or adding tests beyond the ones the spec scenarios call for.
- Making the live/golden suite run in CI.
- Touching the OpenSpec-generated agent files (`.agents/`, `.claude/`, `.gemini/`,
  `.github/prompts|skills|agents`, `.opencode/`). They are regenerated by `openspec update`.

## Decisions

### D1. Ruff rule set: E, F, W, I, B, UP at line length 120, E501 ignored
`select = ["E", "F", "W", "I", "B", "UP"]`, `line-length = 120`,
`target-version = "py311"`, `ignore = ["E501"]`. These catch real bugs (F, B), keep imports
tidy (I) and modernize syntax (UP) without style opinions about the existing dense code. E501
is ignored because the 54 long lines are mostly data tables and URLs; wrapping them is churn.
E702 (semicolon statements) stays on, and those 16 sites get split. Exclude the
OpenSpec-generated directories and `docs/` from lint scope.
- *Alternative:* adopt one contributor's broad personal rule set (BLE, S, RUF, …). Rejected:
  the result would hinge on taste, and the existing `# noqa: BLE001` comments show blind
  excepts are deliberate in `doctor`.
- *Alternative:* `ruff format` as well. Rejected for now: 45 files would be rewritten and the
  diff would bury the meaningful changes. It can be a later change.

### D2. Pin ruff in the dev group and invoke it through uv
Add `ruff` to `[dependency-groups].dev` so `uv.lock` pins it, and run `uv run ruff check`
both locally and in CI. This satisfies "same locally and in CI". The project config also
overrides user-level config, because ruff uses the closest `pyproject.toml` that has a
`[tool.ruff]` table.
- *Alternative:* `uvx ruff` or `astral-sh/ruff-action`. Rejected: the version would float
  apart from the lockfile.

### D3. CI workflow shape
Add `.github/workflows/ci.yml`. It triggers on `push` and `pull_request`, runs one job on
`ubuntu-latest` with `permissions: contents: read`, and has these steps: checkout →
`astral-sh/setup-uv` (with cache) → `uv sync --locked --group dev` →
`uv run ruff check` → `uv run pytest -m "not live"`. It uses one Python, the one `uv` picks
from `requires-python`. No matrix: the code is pure Python with no platform branches, and a
matrix triples minutes for no signal. Playwright browsers are not installed, because no
offline test launches one. If one does, the test belongs under `live`.
- *Alternative:* fold into `copilot-setup-steps.yml`. Rejected: that file is generated and
  only runs when it changes.

### D4. `tests/support/` package with explicit imports
Create `tests/__init__.py` and `tests/support/__init__.py`. Move `cce_rebuild.py`,
`ecs_rebuild.py`, `ecs_ri_rebuild.py`, `elb_rebuild.py`, `evs_rebuild.py`, `obs_rebuild.py`,
`rds_rebuild.py`, `sfs_rebuild.py`, `simple_rebuild.py`, `golden.py`, `render.py` and
`template_audit.py` with `git mv` so history follows. Imports become
`from tests.support import golden`, and `importlib.import_module(f"tests.support.{name}")`
replaces bare names. Set `pythonpath = .` in `pytest.ini`. This is pytest's own setting for
putting the rootdir on the path, which makes `tests` importable as a package. Then delete the
loop in `conftest.py`. `autocalc` already resolves from the installed project
(`uv sync` installs it in editable mode).
- *Alternative:* `pytest --import-mode=importlib` with no `__init__.py`. Rejected: helpers that
  import each other (`template_audit` → `golden`) still need a package root.
- *Alternative:* keep the helpers in `tests/` and rename them `_helpers`. Rejected: that keeps
  the bare-module import problem.

`template_audit.py` and `render.py` are runnable scripts. They keep their `__main__` entries
and are invoked as `uv run python -m tests.support.<name>`. Update the docs that show the old
paths: `README.md` (`uv run python tests/render.py`) and `docs/CAVEATS.md`
(`tests/golden.compare_cards`, `tests/template_audit.py`).

### D5. Bundle on demand: `scripts/fetch_bundle.py`
Add a script that uses `httpx`, which is already a dependency:
1. GET `calculator.html` and extract the version with the same regex `doctor` uses.
2. GET `https://portal.hc-cdn.com/CBC-PortalCalculator/<ver>/framework.js`.
3. Write it to `.cache/bundle/framework-<ver>.js`, print the path, and exit non-zero with a
   clear message if the version is not found.

Accept an optional `--version` to fetch a specific historical build such as 11.4.201, which
the docs cite. Add `.cache/` to `.gitignore`. Docs replace "`docs/evidence/bundle/framework.js`"
with "run `uv run python scripts/fetch_bundle.py`, then search the printed file". Delete the
committed file with `git rm`. If `docs/evidence/` is then empty, it goes too.
- *Alternative:* a CLI subcommand (`autocalc bundle fetch`). Rejected: this is a
  contributor/reverse-engineering tool, not a product surface, and adding it would mean
  amending the `mcp-surface` and CLI expectations.
- *Alternative:* git LFS. Rejected: that still redistributes third-party code.

### D6. Lint fixes are behavior-preserving
Apply `ruff check --fix` (safe fixes only) first. Then fix the rest by hand: split E702 lines,
add `from exc` for B904, and add `strict=` to `zip` for B905. Pick `strict=True` only where
equal lengths are already guaranteed; otherwise use `strict=False` to keep today's behavior.
Prefix unused loop variables with `_`, and for B017 assert the specific exception the code
raises. Every hand fix must keep the offline suite green and pass a live smoke check
(`pytest -m live -k golden`) on a machine that has the corpus.

## Risks / Trade-offs

- [The offline suite passes locally only because corpus fixtures exist] → Before enabling CI,
  run `pytest -m "not live"` with `tests/fixtures/corpus` moved aside. Any failure means a
  test is missing the `live` marker or a helper reads the corpus at import time. Fix it in
  this change.
- [`strict=True` on `zip` could raise where lengths differ today] → Default to `strict=False`
  unless equal lengths are obvious (D6).
- [Deleting the bundle loses the exact 11.4.201 build if Huawei's CDN purges old versions] →
  It stays in git history (`git show 5644802:docs/evidence/bundle/framework.js`). CAVEATS
  notes that recovery path in one line.
- [Importing via `tests.support` breaks someone's local script that imported `golden`] →
  Contributors only; noted as BREAKING in the proposal.
- [The `.agents/` etc. directories contain Markdown only, but ruff could still scan them] →
  Exclude them explicitly in `[tool.ruff]` so a future generated `.py` cannot fail CI.

## Migration Plan

Land everything on one branch in this order: ruff config and fixes → test move → bundle
removal → CI workflow last, so the first CI run sees the cleaned tree. To roll back, revert
the merge commit. Nothing is deployed and no user data is touched.
