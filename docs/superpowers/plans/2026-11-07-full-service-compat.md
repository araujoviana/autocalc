# Full service compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every one of the 97 calculator services can be quoted in every billing mode and configuration its page sells, and each claim is backed by a live replay on the real page. IaaS first.

**Architecture:** A live compatibility harness (generalised from the audit's `obs-replay.ts` and `obs-states.ts`) drives the real page anonymously with the form state our builders produce and diffs the page's card against ours. Each service is "done" only when its scenario matrix is green on the harness. Fixes go in the builders/recipes/schemas; findings go in `docs/compat/<service>.md`, generated by the harness.

**Tech Stack:** Bun, TypeScript, Playwright (existing `BrowserManager`, `Driver`, `encodeCard`), zod schemas in `src/core/schemas.ts`, form recipes in `src/core/services/forms.ts`, schema yaml in `src/schema/files/`.

**Spec:** `docs/research/compat-audit-2026-11-07.md` (findings), `docs/roadmap.md` item 7b, `openspec/specs/huawei/page-encoding/spec.md`.

## Global Constraints

- Must work on Windows and Linux (memory: platform-targets); no shell-only helpers in `src/`.
- No GitHub issues: open items go in `docs/roadmap.md`.
- Live runs are anonymous and save nothing; tests that need a stored session stay in `tests/live/` and out of `test:offline`.
- Offline gate before every commit: `bun test tests/unit tests/integration`, `bun run check`, `bun run check:boundaries`.
- Remove a roadmap row in the same commit that closes it.
- No attribution lines in commit messages.
- Deep Archive does not exist as a feature: out of scope everywhere.

```ts
export type Product = Record<string, any>;
export type Tuple = [number | null, number | null, number | null];
export interface Diff { key: string; builder?: Tuple; page?: Tuple }

const key = (p: Product) => String(p.usageFactor ?? p.resourceSpecCode);
const n = (v: unknown): number | null => v === undefined || v === null || v === "" ? null : Number(v);
const tuple = (p: Product): Tuple => [n(p.usageValue), n(p.usageMeasureId), n(p.productNum)];

/** Products of the builder's card against the products of the card the page built. */
export function diffProducts(built: Product[], page: Product[]): Diff[] {
  const b = new Map(built.map(p => [key(p), p])), g = new Map(page.map(p => [key(p), p]));
  const out: Diff[] = [];
  for (const k of new Set([...b.keys(), ...g.keys()])) {
    const x = b.get(k), y = g.get(k);
    if (!x || !y) { out.push({ key: k, ...(x ? { builder: tuple(x) } : {}), ...(y ? { page: tuple(y) } : {}) }); continue; }
    const tx = tuple(x), ty = tuple(y);
    if (tx.some((v, i) => v !== ty[i])) out.push({ key: k, builder: tx, page: ty });
  }
  return out;
}
```

```ts
import { BrowserManager } from "../../../src/core/browser.ts";
import { encodeCard } from "../../../src/core/page/encode.ts";
import { CardInput } from "../../../src/core/schemas.ts";
import { buildCard } from "../../../src/core/services/index.ts";
import { diffProducts, type Diff } from "./harness.ts";

export interface Scenario { name: string; input: Record<string, unknown> }
export interface Result { name: string; ok: boolean; stage: "schema" | "build" | "page" | "diff" | "ok"; message?: string; diff?: Diff[] }
export type Catalog = { product: Record<string, Record<string, unknown>[]> };

const context = (catalog: Catalog) => ({
  productInfo: async () => catalog,
  rate: async (body: any) => ({ productRatingResult: body.productInfos.map(({ id }: any) => ({ id, amount: 0, originalAmount: 0 })) }),
}) as any;

export async function runScenario(manager: BrowserManager, service: string, region: string, catalog: Catalog, scenario: Scenario): Promise<Result> {
  const parsed = CardInput.safeParse({ service, region, ...scenario.input });
  if (!parsed.success) return { name: scenario.name, ok: false, stage: "schema", message: parsed.error.issues.map(i => i.message).join("; ") };
  let built: any;
  try { built = await buildCard(parsed.data, context(catalog)); }
  catch (e: any) { return { name: scenario.name, ok: false, stage: "build", message: String(e?.message ?? e).slice(0, 300) }; }
  let page: any;
  try { page = await encodeCard(manager, service, built.rewriteValue, { timeout: 25 }); }
  catch (e: any) { return { name: scenario.name, ok: false, stage: "page", message: String(e?.message ?? e).slice(0, 300) }; }
  const diff = diffProducts(built.selectedProduct.productAllInfos, page.selectedProduct.productAllInfos);
  return diff.length ? { name: scenario.name, ok: false, stage: "diff", diff } : { name: scenario.name, ok: true, stage: "ok" };
}
```

## Procedure for every later service (Tiers 1 to 5)

Each service gets its own short plan under `docs/superpowers/plans/`, written at the start of its tier after step 1, using exactly these steps:

1. **Inventory.** `bun tests/support/compat/run.ts --states <service>` writes the visible controls per page state; `productInfo` for the primary regions (sa-brazil-1, la-south-2, ap-southeast-3) gives billing modes, groups and usage factors. Output goes to `docs/compat/<service>.md` under "Page" and "Catalog".
2. **Matrix.** Write `scenarios/<service>.ts`: one scenario per billing mode (ondemand, monthly, yearly, plus RI/one-time where the catalog has them) crossed with each option that changes controls, each option set to a distinct non-default value. Include the boundary of every stepper range the dump reports.
3. **Red.** Run the harness. Every failure is a finding with a stage (`schema`, `build`, `page`, `diff`).
4. **Green.** Fix in this order: form-state order (select controls before typing), control id mapping (check against a real corpus card in `tests/fixtures/corpus/`), units, schema bounds, missing options, missing billing modes. One commit per fixed class of failure, each with an offline test that would have caught it.
5. **Close.** The service's section in `docs/compat/<service>.md` shows all scenarios green; `autocalc supported` lists every billing mode the page sells; the roadmap row is removed; `ACCEPTED_DEFAULT_ONLY`/`VERIFIED` in `publication.ts` is updated.
6. **Services that do not fit.** If the page has no price (quote on request, contact sales) or needs a console login to price, record it in `docs/compat/<service>.md` as "not quotable" with the evidence, and make `autocalc describe` say so. Do not fake a card.
